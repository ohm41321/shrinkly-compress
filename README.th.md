## ภาพรวม

Shrinkly ช่วยเตรียมไฟล์ให้ผ่านข้อจำกัดขนาดของแพลตฟอร์มต่าง ๆ เช่น Discord
ที่จำกัด 10 MB โดยไม่ส่งไฟล์ที่เลือกไปยังเซิร์ฟเวอร์ของแอป ระบบคำนวณการบีบอัด
จากขนาดเป้าหมายและตรวจทรัพยากรของอุปกรณ์อัตโนมัติ เพื่อรักษารายละเอียดของภาพ
ให้ดีที่สุดเท่าที่ทำได้และไม่ทำให้เบราว์เซอร์ค้าง

> [!IMPORTANT]
> ไฟล์ที่เลือกจะอยู่บนอุปกรณ์ของคุณ เมื่อบีบอัดวิดีโอ ระบบจะดาวน์โหลด
> FFmpeg WebAssembly runtime จาก jsDelivr ในครั้งแรก แต่จะไม่ส่งวิดีโอของคุณ
> ไปยัง CDN

## จุดเด่น

| | ความสามารถ | รายละเอียด |
| --- | --- | --- |
| 🔒 | **เป็นส่วนตัวตั้งแต่การออกแบบ** | รูปภาพ วิดีโอ และไฟล์ประมวลผลภายในเบราว์เซอร์ |
| 🎯 | **กำหนดขนาดเป้าหมาย** | มีค่า Discord 10 MB, อีเมล 25 MB และกำหนดเองได้ |
| ✨ | **เน้นคุณภาพวิดีโอ** | H.264 แบบ 2-pass กระจาย bitrate ให้ฉากซับซ้อนได้เหมาะสมขึ้น |
| ⚙️ | **ปรับตามกำลังเครื่อง** | ตรวจ CPU, RAM ที่เบราว์เซอร์รายงาน, มือถือ/เดสก์ท็อป และ WebAssembly |
| 🧠 | **ตั้งค่าสื่ออัตโนมัติ** | ปรับความละเอียด fps bitrate ภาพ และงบเสียงตามเป้าหมาย |
| 📦 | **ทำงานหลายไฟล์** | จัดคิว ติดตามผล และดาวน์โหลดแยกหรือรวมเป็น ZIP |
| 🌗 | **หน้าตาใช้งานง่าย** | รองรับมือถือ ภาษาไทย/อังกฤษ และธีมมืด/สว่าง |

## การทำงาน

```text
เลือกไฟล์ → กำหนดขนาด → ประมวลผลบนเครื่อง → ดาวน์โหลดผลลัพธ์
```

ระบบเลือกวิธีประมวลผลตามประเภทไฟล์:

| ประเภท | ตัวอย่าง | วิธีบีบอัด | ผลลัพธ์ |
| --- | --- | --- | --- |
| รูปภาพ | JPG, PNG, WebP | ค้นหาคุณภาพด้วย Canvas และลดขนาดตามความจำเป็น | JPEG หรือ WebP |
| วิดีโอ | MP4, MOV และสื่อที่เบราว์เซอร์อ่านได้ | H.264/AAC แบบ adaptive 2-pass | MP4 |
| ไฟล์อื่น | เอกสาร ไฟล์บีบอัด และไฟล์ทั่วไป | DEFLATE ด้วย JSZip | ZIP |

### ระบบวิดีโอที่เน้นคุณภาพ

1. อ่านระยะเวลาและความละเอียดของวิดีโอ
2. คำนวณ bitrate ภาพและเสียงจากขนาดเป้าหมาย
3. ลดเสียงเหลือ 20–96 kbps เมื่อจำเป็น เพื่อเหลือพื้นที่ให้ภาพมากขึ้น
4. เลือกความละเอียดและเพดาน fps จากจำนวนบิตต่อพิกเซลที่ใช้ได้
5. เข้ารหัสรอบแรกเพื่อวิเคราะห์การเคลื่อนไหวและความซับซ้อนของฉาก
6. เข้ารหัสรอบสองเพื่อกระจาย bitrate ไปยังส่วนที่เห็นผลด้านคุณภาพมากที่สุด

ระบบจะไม่เพิ่ม fps สูงกว่าต้นฉบับ ลบ metadata ใช้ H.264/AAC ที่รองรับได้กว้าง
และปรับ MP4 ให้เริ่มเล่นผ่านเครือข่ายได้เร็วขึ้น

### การเลือกทรัพยากรอัตโนมัติ

ข้อมูลฮาร์ดแวร์ที่เบราว์เซอร์เปิดเผยเป็นเพียงค่าประมาณ Shrinkly จะใช้ข้อมูล
เท่าที่มีและเลือกค่าปลอดภัยเมื่อไม่สามารถตรวจบางรายการได้

| สภาพแวดล้อมที่ตรวจพบ | Threads | Preset | การทำงาน |
| --- | ---: | --- | --- |
| โหมดเข้ากันได้หรือ RAM จำกัด | 1 | `fast` | ใช้ทรัพยากรสูงสุดน้อยและรองรับได้กว้าง |
| เดสก์ท็อประดับทั่วไป | 2–3 | `medium` | บีบอัดได้มีประสิทธิภาพโดยไม่ใช้ทุก core |
| เดสก์ท็อปประสิทธิภาพสูง | 4 | `slow` | โปรไฟล์คุณภาพสูงสุด |
| อุปกรณ์มือถือ | ไม่เกิน 2 | `medium` หรือ `fast` | จำกัดภาระ CPU และหน่วยความจำต่อเนื่อง |

ระบบเว้น logical CPU cores ไว้อย่างน้อยครึ่งหนึ่ง ทำทีละวิดีโอ
ลบข้อมูลชั่วคราวจาก 2-pass และคืนหน่วยความจำของ FFmpeg หลังจบงานชุดนั้น

> [!NOTE]
> WebAssembly แบบ multi-thread ต้องใช้ cross-origin isolation โดย
> `vercel.json` ตั้งค่า COOP/COEP สำหรับ Vercel ไว้แล้ว หากโฮสต์อื่นไม่ได้ตั้ง
> header ที่เทียบเท่า ระบบจะเปลี่ยนเป็นโหมด 1 thread โดยอัตโนมัติ

## ความเป็นส่วนตัว

- ไฟล์ที่เลือกไม่ถูกอัปโหลดไปยังเซิร์ฟเวอร์ของ Shrinkly
- รูปภาพประมวลผลด้วย `createImageBitmap` และ Canvas API
- วิดีโอประมวลผลด้วย FFmpeg WebAssembly ภายในเบราว์เซอร์
- ไฟล์ทั่วไปบีบอัดด้วย JSZip ภายในเบราว์เซอร์
- ไฟล์วิดีโอชั่วคราวและ log ของ 2-pass ถูกลบหลังประมวลผล
- FFmpeg ในหน่วยความจำถูกปิดเมื่อคิวทำงานเสร็จ

การบีบอัดวิดีโอครั้งแรกต้องใช้อินเทอร์เน็ตเพื่อดาวน์โหลด FFmpeg runtime
ครั้งถัดไปเบราว์เซอร์อาจโหลดจาก cache ได้

## เริ่มต้นใช้งาน

### สิ่งที่ต้องมี

- Node.js 20 ขึ้นไป
- npm
- เบราว์เซอร์สมัยใหม่

### รันในเครื่อง

```bash
git clone https://github.com/ohm41321/shrinkly-compress.git
cd shrinkly-compress
npm ci
npm run dev
```

เปิด [http://localhost:3000](http://localhost:3000)

### สร้าง Production build

```bash
npm run build
```

Next.js จะ export เว็บ Static ไปยัง `out/` และ post-build script จะคัดลอก
ผลลัพธ์เดียวกันไปยัง `dist/`

```text

├── app/
```

## ข้อจำกัด

- การลดวิดีโอจาก 300 MB เหลือ 10 MB คือการตัดขนาดเดิมออกประมาณ 97%
  ระบบ 2-pass ช่วยกระจาย bitrate ได้ดีขึ้น แต่ไม่สามารถเก็บรายละเอียดต้นฉบับ
  ได้ทั้งหมด
- วิดีโอยาวหรือมีการเคลื่อนไหวมากอาจต้องลดความละเอียด fps หรือ bitrate
  เพื่อให้ไม่เกินเป้าหมาย
- วิดีโอขนาดใหญ่มากติดข้อจำกัด RAM ของเบราว์เซอร์และ WebAssembly
  หากทำงานกับไฟล์ประมาณ 1 GB ขึ้นไปเป็นประจำ โปรแกรม Native จะเหมาะกว่า
- ไฟล์ที่บีบอัดอยู่แล้ว เช่น JPEG, MP4, ZIP และ PDF อาจไม่เล็กลงเมื่อใส่ ZIP
- ข้อมูลประกอบของ container และพฤติกรรม codec อาจทำให้ขนาดผลลัพธ์ต่างจาก
  เป้าหมายเล็กน้อย
